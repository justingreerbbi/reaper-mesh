# Inbox and live radio diagnostics v1

The inbox has its own sequence space; it never shares configuration revisions/events. The device retains eight complete messages in a bounded ring and advertises oldest/latest sequence numbers. The agent retains up to 32 received messages. Reconnect preserves a completed cursor on the same device/boot, restarts partial retrieval from its first chunk, and uses read-only queries. A new boot resets the remote cursor. Retention gaps are visible; they do not silently reset configuration or imply delivery of missing messages.

Welcome feature bit 5 advertises live radio diagnostics. Radio query/status uses an independent request counter and includes authoritative settings revision, probe result, effective state/reason, RX/TX counters, free heap and minimum free main-task stack in bytes. Only an outstanding matching request/boot/revision can update agent diagnostics. Three unanswered probes stop diagnostic polling without extending USB health deadlines or concealing a missing pong. Counter values do not certify over-air delivery.

Welcome feature bit 6 plus inboxVersion 1/inboxCapacity 8 advertises inbox retrieval. Query/head exposes the bounded sequence range; read/item retrieves one 32-byte binary chunk encoded as canonical lowercase hex. Missing replies identify evicted or invalid sequence/part requests. Each item repeats origin, stable message ID, numeric channel and chunk metadata. The agent correlates every response, validates consistent metadata, bounds all buffers, and publishes only complete valid UTF-8. Read retries stop after three attempts; no inbox operation executes a send or configuration mutation. Received message identities bind their content within retention.

Sending to the connected node's own device ID performs explicit local delivery: the message is accepted into that node's inbox and the result is acknowledged with reason local-delivery, without claiming a radio transmission. This enables meaningful one-board USB/application checks. Remote sends require mesh mode, a working radio, confirmed US hardware/antenna and airtime admission. Off/receive-only/unconfirmed/fault states return a failed remote result rather than pretending it was transmitted. Broadcast never produces recipient ACKs.

The board radio adapter uses a pinned Semtech driver behind bounded busy/SPI operations. SPI transaction buffers remain alive if native completion times out; the bus then fails closed and cannot reuse pending transaction storage. A boot probe performs setup/calibration without enabling TX. Off holds the SX1262 reset after the probe. Receive mode never transmits, including ACKs or relays. Policy changes cancel pending/in-flight radio work before reconfiguration; this cannot undo RF already emitted.

Inbox protocol version 2 appends the original RF destination to each received item (`broadcast` or the addressed node identity). This lets agents keep channel broadcasts out of direct-message threads while preserving channel IDs. Version-1 firmware remains readable; those older inbox items lack destination metadata and are shown only in their channel view because their original route cannot be reconstructed. The web portal groups configured channel slots separately from peer conversations.
The screen shows the radio state, and its pages are in [Device screen and buttons](device-display.md). Diagnostics expose probe failures even when the requested mode is off. User-confirmed antenna facts are recorded in the board profile; no timezone-based region inference is allowed.

An inbox item may hold bytes that are neither text nor a known envelope. See [Agent features, payloads and inbox alert](protocol.md#agent-features-payloads-and-inbox-alert-d50).
